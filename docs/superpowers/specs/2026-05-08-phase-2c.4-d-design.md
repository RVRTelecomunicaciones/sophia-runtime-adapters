## 1. Goal and scope

D wires **real alerts to Loki** for log signal export with drill-through dashboards, and introduces the **Grafana annotations layer** for deployment + incident overlays on time-series panels. After D, an operator on-call can:

1. See an alert fire in Slack / PagerDuty / Linear (A+B);
2. Click the alert link → land on a Grafana dashboard with the relevant time window;
3. See the **incident annotation** marking exactly when the alert fired;
4. Click the **"Recent logs"** panel → drill into Loki for the runtime's structured logs at that moment;
5. Correlate via `trace_id` / `span_id` to the related Tempo trace.

D ships log signal infrastructure (Loki + collector pipeline + dashboards) and annotation infrastructure (GHA workflow + new webhook adapter). It does **NOT** ship per-alert runbook authoring — that deuda from 2C.1 lives separately and is expected as a follow-up patch (`v0.9.x`) or fold into C.

### 1.1. In scope (matches roadmap §D)

- Loki container in compose stack (overlay `compose.logs.yaml`).
- Runtime + linear-webhook log signal export to collector via filelog receiver tailing JSONL mirror files (R10 stdout contract preserved alongside).
- `trace_id` + `span_id` + `correlation_id` + `capability` automatically present in log records.
- Loki Grafana datasource provisioning.
- "Recent logs" panel on per-adapter dashboards (4 dashboards).
- Annotations layer: GHA workflow on tag push (deploys) + new `grafana-annotations-webhook` adapter (incidents driven by alertmanager).
- `CHANGELOG 0.9.0` + `v0.9.0` tag.

### 1.2. Out of scope (per roadmap + this spec's clarifications)

- Per-alert runbook authoring (`docs/runbook/*.md`) — separate scope, follow-up.
- Log retention sizing for production — operational decision in C.
- Log-based alerting (Loki ruler) — Phase 3 candidate.
- PII redaction policy — operational, not code.
- In-process log rotation — disk-fill is operational risk; if needed, separate scope with strong tests.
- Multi-org / multi-tenant Grafana routing — V1 single-instance.
- Scoped (dashboardUID/panelId) annotations — V1 is global.
- Annotation dedup / state — V1 is stateless append-only (consistent with I-AB.7 from A+B).

## 4. Data flow

Three disjoint flows. Each hop traced with data shape + failure mode.

### 4.1. Log flow (runtime → Loki → Grafana)

```
[runtime code]
   logger.InfoContext(ctx, "execution started", "capability", "shell.exec@v1")
        │
        ▼
[OTelContextHandler.Handle]
   record.AddAttrs(slog.String("trace_id", ...), slog.String("span_id", ...))   ← if active span
        │
        ▼
[slog.JSONHandler]
   {"time":"…","level":"INFO","msg":"execution started","capability":"shell.exec@v1",
    "trace_id":"...","span_id":"...","correlation_id":"...","tenant_type":"test"}\n
        │
        ▼
[safe fanout writer — stdout primary, mirror best-effort secondary]
   ├──► os.Stdout  (R10 contract)
   └──► /var/log/<service>/<service>.jsonl  (volume mount)
        │
        ▼ (bind-mounted volume, host filesystem)
[otel-collector filelog receiver]
   tail-follow include=[/var/log/runtime-adapters/runtime.jsonl,
                        /var/log/linear-webhook/linear-webhook.jsonl,
                        /var/log/grafana-annotations-webhook/grafana-annotations-webhook.jsonl]
   start_at: end
   parse JSON → log record; OTel resource attribute `service.name` set explicitly per include path
        │
        ▼
[batch processor]
   default size=8192, timeout=200ms
        │
        ▼
[otlphttp/loki exporter]
   endpoint: http://loki:3100/otlp     (the exporter completes the OTLP-specific subpath internally)
   OTLP-encoded Logs payload, gzip
        │
        ▼
[Loki OTLP receiver]
   translate OTLP → Loki streams; stream key = {service, level, environment, tenant_type?}
   line = full JSON payload (parseable at query time via | json)
        │
        ▼
[Loki TSDB filesystem]
        │
        ▼
[Grafana Loki datasource]
   LogQL: {service="runtime-adapters",level="info"} | json | capability="shell.exec@v1"
        │
        ▼
[Grafana "Recent logs" panel render]
```

**Failure modes:**

| Hop | Mode | Behavior |
|---|---|---|
| MultiWriter → stdout | broken pipe (rare) | record dropped; process does not panic; subsequent writes resume after pipe restored |
| MultiWriter → mirror file | write error (disk full, permission revoked after startup) | stdout continues; mirror writes degraded; error log throttled (per D2C4D.10) |
| filelog receiver | offset checkpoint corrupted | re-reads from `start_at: end`; no replay |
| batch processor | queue full (Loki slow) | collector / exporter buffers until retry / queue limits; after limits are exceeded, records may be dropped |
| otlphttp/loki exporter | Loki 5xx / transport | exponential backoff retry |
| otlphttp/loki exporter | Loki 429 | back off; same as above |
| Loki ingestion | bad payload (label cardinality limit) | Loki rejects with 400; exporter does not retry 4xx; record dropped; visible in collector logs |
| Loki TSDB | disk fill | Loki rejects writes with 5xx | operational; out of scope |

### 4.2. Deploy annotation flow (GHA → Grafana)

```
[operator]      git tag v0.X.Y && git push --tags
        ▼
[GitHub Actions trigger on: push: tags: ['v*.*.*']]
        ▼
[annotate-deploy.yaml job]
   step 1: check secrets present → if missing, echo "skipped" and exit 0
   step 2: curl -sSf -X POST -H "Authorization: Bearer $TOKEN"
           --data '{"text":"deploy v0.X.Y (sha)","tags":["deploy","test"],"time":<ms>}'
           "${GRAFANA_URL}/api/annotations"
        ▼
[Grafana annotations API]
   200 OK → annotation persisted to Grafana DB
        ▼

```

**Failure semantics:**

- Network / Grafana down → curl fails → workflow goes red. Tag is NOT reverted; deploy is not blocked; operator may re-run or ignore (next deploy creates its own annotation).
- Token revoked → 401 → workflow fails; rotate token.

### 4.3. Incident annotation flow (alertmanager → adapter → Grafana)

```
[Prometheus] evaluate rule → alert fires
        ▼
[Alertmanager router]
   severity=critical → ops-critical
   severity=warning  → ops-warnings
   severity=info     → null-receiver (silenced; I-AB.1)
        ▼
[Alertmanager receiver fanout — all targets in parallel (dispatcher independence)]
   ops-critical:  pagerduty + slack #incidents + grafana-annotations-webhook ★
   ops-warnings:  slack #ops + linear-webhook + grafana-annotations-webhook ★
        ▼
[POST http://grafana-annotations-webhook:9096/webhook]
   alertmanager v4 webhook payload, JSON
        ▼
[handler.WebhookHandler.ServeHTTP]
   1. Method != POST → 405
   2. Body not valid JSON → 400
   3. Parse → AlertmanagerWebhookV4
        ▼
[mapper.MapAlertmanagerWebhookToAnnotations(payload)]   pure function
   for each alert in payload.alerts[]:
      emit AnnotationRequest{
        text:    "[CRIT|WARN] <alertname> — <summary>",
        time:    alert.startsAt.UnixMilli(),
        timeEnd: alert.endsAt.UnixMilli() if !zero,
        tags:    [alertname, "severity:"+severity, "status:"+alert.status, "source:alertmanager"],
        // V1: NO dashboardUID, NO panelId — global annotation
      }
        ▼ (loop, sequential per group)
[client.HTTPGrafanaClient.PostAnnotation(ctx, req)]
   POST ${GRAFANA_URL}/api/annotations  with Authorization: Bearer ${TOKEN}
```

**Status mapping (D2C4D.12 — deliberate divergence from linear-webhook):**

| Grafana response | GrafanaClient error | Adapter HTTP response | Alertmanager behavior |
|---|---|---|---|
| 200 / 201 | nil | 204 No Content (final) | success; annotation rendered |
| 5xx / transport / timeout | `ErrGrafanaClient5xx` | **502 Bad Gateway** | retry per Alertmanager's notifier retry / backoff behavior |
| 429 Too Many Requests | `ErrGrafanaClient5xx` (treated as transient) | **503 Service Unavailable** | retry with backoff |
| 400 / 401 / 403 / 404 | `ErrGrafanaClient4xx` | **204 No Content** *(deliberate — see below)* | NO retry — stop |
| Mixed (some 200, some 5xx) | partial — adapter responds 502 | retry whole group | next attempt re-creates the 200s (annotations are cheap dups, better than loss) |

**Why 204 on 4xx (documented divergence):**

linear-webhook responds 500 on 4xx to force retry (its model: "Linear is source of truth, eventual consistency wins"). grafana-annotations-webhook **deliberately diverges**: annotations are not source of truth — they are visual hints. If Grafana rejects with a 4xx (token without permissions, malformed payload), retrying infinitely amplifies the operational problem without value. Better: log the error with full context, respond 204, let the operator resolve the root cause.

**Accepted risk**: token revoked during an incident → annotations skipped silently (visible in adapter logs + alertmanager metrics). Operator monitors via "missing annotations" in post-mortem.

**V1 scope (D2C4D.14, D2C4D.15):**
- 1 alertmanager webhook payload → N annotation POSTs (one per alert in the group).
- Stateless. No dedup between payloads.
- No `dashboardUID` / `panelId` — global annotations on all dashboards. Operator filters via tags.

### 5.1. Reliability hierarchy

(See §2.1 component map; failure isolation matches the diagram.)

### 5.2. Cross-component invariants under failure

| ID | Invariant | Enforcement |
|---|---|---|
| **I-D.1** | Stdout remains the primary R10 output. Downstream components do not affect stdout. Mirror-file failures must not block stdout writes. If stdout itself fails, the process must not panic; the record may be lost. | logger MultiWriter writes stdout first, mirror second; both writers wrapped to prevent panics; stdout failure logged once per epoch via throttled error path. |
| **I-D.2** | Alertmanager dispatcher independence preserved. A failure in `grafana-annotations-webhook` does NOT block PagerDuty, Slack, or `linear-webhook`. Extends I-AB.6. | webhook_configs additional in each receiver; alertmanager fans out all targets in parallel; routing tree shape unchanged. Test asserts all 4 webhook entries in correct receivers. |

| **I-D.4** | A+B alert delivery contract intact. Routing tree shape, group_by, inhibit_rules, timing UNCHANGED. D only adds `webhook_configs` entries; zero modifications to the tree. | `alertmanager_routing_test.go`: existing tests pass without modification; new tests are additive. |

### 5.3. Per-component failure response (consolidated)

| Failure event | Runtime impact | Log visibility | Alert delivery | Annotation impact | Recovery |
|---|---|---|---|---|---|
| Loki container down | none | stdout intact (R10) | none | **none** — Grafana annotations API is independent of Loki; only log queries / "Recent logs" panel affected | self-heals on restart; collector exporter retries; some records dropped if outage exceeds queue limits |
| otel-collector OOM / crash | none | stdout intact | none | none — adapter is independent of collector | restart resumes from filelog offset checkpoint |
| Disk full on logs volume | runtime drops record on file write error (stdout still tries) | stdout still flushed (R10) | none | none | operational risk per D2C4D.11; operator monitors |
| `grafana-annotations-webhook` adapter down | none | none | other webhooks fire (I-D.2) | annotations skipped during outage | self-heals on restart; alertmanager retries failed webhook notifications according to its notifier retry / backoff behavior |
| Grafana service down | none | log queries fail in UI | none | NEW deploys: GHA workflow fails (no-op or red — see §4.2); incident webhooks: 5xx → adapter responds 502 → retry | self-heals; deploy annotations have no retry by design |
| Grafana token revoked | none | none | none | NEW deploys: 401 → workflow red; incident webhooks: 4xx → adapter responds 204 (no retry) | rotate token; subsequent annotations resume |
| Loki cardinality limit hit | none | stdout intact | none | annotations unaffected | bug fix in label config; CI gate (§6.5) catches at PR time |
| Loki OTLP 429 | none | stdout intact | none | none | exporter back off; collector / exporter buffers until retry / queue limits; after limits exceeded, records may be dropped |
| alertmanager fanout duplicates webhook (regression) | none | none | minor — duplicate annotations | tagged dups visible in dashboard | regression test in `alertmanager_routing_test.go` catches in CI |
| Volume bind-mount mis-configured | runtime emits OK to stdout; mirror file write fails | stdout intact (R10) | none | none | error visible at runtime startup if `RUNTIME_LOG_MIRROR_PATH` not writable (fail-fast per R10) |

## 8. Decisions

| ID | Decision |
|---|---|
| **D2C4D.1** | Roadmap §D scope strict: Loki + log export + drill-through + annotations. Per-alert runbooks NOT in D — separate deuda. |
| **D2C4D.2** | Log transport: collector filelog receiver tailing JSONL mirror files (NOT OTel SDK direct log signal; NOT Docker container log mounts). Justification: R10 stays intact; logs survive collector outages; portable across Linux + macOS + future k8s with sidecar/emptyDir. |
| **D2C4D.3** | Mirror file dual-write: runtime emits to BOTH stdout (R10, primary) AND `/var/log/<service>/<service>.jsonl` (mirror, best-effort secondary) via a safe fanout writer. Mirror failures MUST NOT affect stdout writes; mirror errors logged with throttling. |
| **D2C4D.4** | Loki ingest path: native OTLP via `otlphttp/loki` exporter targeting `http://loki:3100/otlp`. Avoids legacy `loki` exporter quirks (label translation, structured metadata). |
| **D2C4D.5** | Compose strategy: separate overlay `compose.logs.yaml`. ADR 0008 envelope preserved. Same pattern as A+B's `compose.receivers.yaml`. |
| **D2C4D.6** | Annotations layer: semi-automated. GHA on tag push (deploys) + new `grafana-annotations-webhook` adapter (incidents driven by alertmanager). |
| **D2C4D.7** | `grafana-annotations-webhook` shape: hybrid C — flat package layout under `internal/integrations/grafana/`; NO domain/ports/application/infrastructure subdirs; NO lifecycle / state / dedup / DB. Files: `client.go`, `types.go`, `mapper.go`, `handler.go`, `config.go` + `cmd/grafana-annotations-webhook/main.go`. |
| **D2C4D.8** | Loki label set: `service`, `level`, `environment`, optional `tenant_type`. Forbidden as labels: `trace_id`, `span_id`, `correlation_id`, `capability`, `adapter`, `error_class`, `retry_hint`, `request_id`, `user_id`, `project_id`, `tenant_id`. |
| **D2C4D.9** | Logger trace correlation: `OTelContextHandler` wraps `slog.JSONHandler` and extracts span context from ctx; inserts `trace_id` + `span_id` when an active span exists. |
| **D2C4D.10** | Mirror lifecycle: empty `RUNTIME_LOG_MIRROR_PATH` → stdout only (R10 pure); non-empty + invalid at startup → fail-fast; non-empty + failure after startup → stdout continues, mirror degraded, error log throttled, process does not panic. |
| **D2C4D.11** | No log rotation in V1. Disk-fill is operational risk; rotation deferred as separate scope with strong tests. |
| **D2C4D.12** | `GrafanaClient` status mapping: 5xx / transport / 429 → `ErrGrafanaClient5xx` → adapter responds 502/503 (retry); 4xx non-transient → `ErrGrafanaClient4xx` → adapter responds 204 (NO retry). Deliberate divergence from linear-webhook (see §4.3 for rationale). |
| **D2C4D.13** | Alertmanager fanout: ops-critical AND ops-warnings each gain ONE `webhook_configs` entry to grafana-annotations-webhook. Routing tree shape, group_by, inhibit_rules, timing UNCHANGED (preserves D2C4AB.1). No-duplication regression test enforces. |
| **D2C4D.14** | V1 annotations are global (no `dashboardUID`, no `panelId`). Tag-based filtering supported via `GET /api/annotations?from=...&to=...&tags=...`. |
| **D2C4D.15** | V1 = one annotation per alert within alertmanager webhook group. Stateless adapter; no dedup. |
| **D2C4D.16** | The OTel **resource attribute** `service.name` is set explicitly per filelog include path (NOT inferred from filename, NOT a log-record-level attribute only). This ensures deterministic Loki stream-key assignment and consistent semantic conventions for trace/log/metric correlation. |
| **D2C4D.17** | GHA deploy-annotation workflow no-op when secrets absent; failures don't revert tag, don't block artifact, don't block subsequent deploys. |

## 13. Glossary (D-specific)

- **Mirror file** — a JSONL file in a shared volume that the runtime writes to in addition to stdout, allowing the otel-collector's filelog receiver to tail it without touching Docker's container log paths.
- **Global annotation** — a Grafana annotation with no `dashboardUID` or `panelId`, rendered on all dashboards.
- **Dispatcher independence** — Alertmanager's behavior of fanning out a single alert to all configured receivers in parallel; one slow or failing receiver does not block others.
- **Layer 3 mode lock** — runtime aborts startup under `CI=true && RUNTIME_TENANT != "test"`. Established in A+B; applies identically to `cmd/grafana-annotations-webhook`.
- **Layer 4 tenant fingerprint** — adapter logs its tenant identifier at startup and aborts under `CI=true && <ADAPTER>_TENANT_TYPE != "test"`. For D: `GRAFANA_TENANT_TYPE`.
